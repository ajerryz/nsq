# quick start


# 各个组件的作用
- nsq_stat: 命令行工具，用于查看 NSQ 集群的统计信息。
- nsq_tail: 命令行工具，用于实时查看指定主题 / 通道的消息内容（类似 tail -f）。
- nsq_to_file: 消息导出工具，用于将指定主题的消息持久化到本地文件。
- nsq_to_http: 消息转发工具，用于将消息发送到 HTTP 服务端点。
- nsq_to_nsq: 跨集群消息同步工具，用于将一个 NSQ 集群的消息转发到另一个 NSQ 集群。
- nsqadmin:
  - NSQ 的Web 管理界面，用于监控和管理整个 NSQ 集群。
    - 可视化展示主题、通道、消息量、消费者状态等
    - 支持查看消息详情、调整节点配置、管理队列等操作
    - 需连接 nsqlookupd 获取集群信息，通过 Web 端口（默认 4171）访问
- nsqd:NSQ 的核心消息代理节点，负责接收、存储和转发消息。
  - 接收生产者发送的消息，按主题（Topic）分类存储
  - 将消息复制到该主题下的所有通道（Channel），分发给订阅的消费者
  - 支持消息持久化（防止节点宕机丢失）和负载均衡
  - 每个 nsqd 是独立节点，可水平扩展形成集群
- nsqlookupd:
  - NSQ 的服务发现组件，负责管理集群拓扑信息。
    - 跟踪所有 nsqd 节点的状态（上线 / 下线）
    - 记录主题和通道的元数据，帮助消费者消费者发现消息来源
    - 多个 nsqlookupd 可部署为集群，避免单点故障
    - nsqd 启动时会向 nsqlookupd 注册，消费者通过 nsqlookupd 找到对应的 nsqd
- to_nsq: 消息生产工具，用于向 NSQ 主题发送消息（从标准输入或文件读取）。
